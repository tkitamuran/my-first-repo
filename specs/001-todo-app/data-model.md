# データモデル: シンプル ToDo アプリ

**日付**: 2026-09-28

## 永続化データ

### TaskStore（保存文書）

localStorage のキー `todo-app.tasks.v1` に保存する最上位オブジェクト。

| フィールド | 型 | 必須 | 規則 |
|---|---|---|---|
| `version` | number | 必須 | 現在は整数 `1` のみ受理する |
| `tasks` | Task[] | 必須 | 登録順を維持した配列 |

### Task（タスク）

| フィールド | 型 | 必須 | 規則 |
|---|---|---|---|
| `id` | string | 必須 | 空でない一意の値。タスクの同一性にだけ使用する |
| `title` | string | 必須 | 前後空白除去後、Unicodeコードポイントで1〜200文字 |
| `completed` | boolean | 必須 | 新規登録時は `false` |

同じ `title` は許可する。操作対象は常に `id` で特定する。登録順はTaskStoreの配列順で表し、
自動的な並べ替えは行わない。

## 画面内状態

永続化せず、アプリ実行中だけ保持する。

| 状態 | 型 | 用途 |
|---|---|---|
| `tasks` | Task[] | 最後に保存へ成功したタスク一覧 |
| `inputError` | string または null | 空入力・文字数超過を入力欄へ関連付ける |
| `storageError` | string または null | 読込・保存失敗を日本語で通知する |
| `pendingDeleteTaskId` | string または null | 削除確認中の対象を識別する |

削除ボタンへのフォーカス復帰先は業務状態へ含めず、UIコンポーネント内の `useRef` で一時保持する。

## 入力の正規化と検証

1. 入力値の前後空白を除去する。
2. `Array.from(normalizedTitle).length` で文字数を数える。
3. 0文字なら「タスクを入力してください。」を返す。
4. 201文字以上なら「タスクは200文字以内で入力してください。」を返す。
5. 正常なら、正規化済み文字列を新しい `Task.title` とする。

検証失敗時は TaskStore と `tasks` を変更しない。

## 状態遷移

| 操作 | 事前条件 | 次状態 | 永続化 |
|---|---|---|---|
| 登録 | 正規化済みタイトルが1〜200文字 | 新規Taskを配列末尾へ追加 | 次状態の保存成功後に確定 |
| 完了 | 対象IDが存在し `completed=false` | 対象だけ `true` | 次状態の保存成功後に確定 |
| 完了解除 | 対象IDが存在し `completed=true` | 対象だけ `false` | 次状態の保存成功後に確定 |
| 削除要求 | 対象IDが存在 | `pendingDeleteTaskId` を設定 | なし |
| 削除取消 | 確認中 | 確認状態を解除 | なし |
| 削除確定 | 確認対象IDが存在 | 対象だけ配列から除外 | 次状態の保存成功後に確定 |

未知のIDに対する完了切替・削除はタスク配列を変更しない。保存失敗時は直前の `tasks` を維持し、
`storageError` を設定する。

## 読込規則

- キーが存在しない場合は、正常な空配列として開始する。
- JSON構文、version、配列、各Taskの型・制約、IDの一意性のいずれかが不正なら、空配列と
  読込エラーを返す。
- 不正な保存値は起動直後には削除・上書きしない。
- 正常な利用者操作を保存した時点で、version 1 の正しい文書へ置き換える。
